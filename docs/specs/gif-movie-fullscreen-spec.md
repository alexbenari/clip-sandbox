# Feature Spec: GIF Movie Full Screen

## Why this matters

During GIF Extraction or Refine Gif, the user needs to inspect a movie across the entire display while keeping the current playback position and range work. This mode is separate from Collection's full screen grid review.

## Terms and current behavior

- **GIF Extraction** is the movie workspace for capturing ranges. **Queue Refine** adjusts a range from its captured-range queue. **Collection-clip Refine** adjusts an extracted clip opened from Collection. Both Refine contexts use `RefineGifScreen` and the shared `FrameReviewPlayerControl`.
- **Exact playback available** means the active player has a review session in the `exact-ready` phase (`captureEnabled` in `src/frame-review/model/frame-review-state.ts`). Collection-clip Refine may open before its source movie is found, so its player may have no session.
- **Exact scrub** means playback is paused on a frame identified by the exact-frame service. **Loop preview** repeatedly plays a selected range. **Staged endpoints** are the start and end frames currently being adjusted before that range is locked.
- The existing movie-position bar seeks during playback and selects exact frames while scrubbing. Screen activation currently mounts and attaches the player; Refine deactivation abandons the active refinement.

## Decisions

| ID | Decision | Reason |
|---|---|---|
| D1 | `F` enters movie full screen only from GIF Extraction, Queue Refine, or Collection-clip Refine while exact playback is available. With no session, during preparation, or after exact preparation fails, `F` does nothing. | The view must have a usable exact-review movie, including when Collection-clip Refine is still finding its source. |
| D2 | Request HTML full screen on the shared player root, rather than the whole document. The player root contains the movie and seek bar; content outside it, including Activity and dialogs, is invisible while full screen is active. | This removes shell chrome and gives the movie mode an element identity distinct from Collection review. Operations needing outside UI must not silently depend on that UI being visible. |
| D3 | The movie fills the display as far as its aspect ratio allows, with black unused space and no cropping or stretching. Full screen scales up the review picture to fit: playback uses a review proxy at most 960 px wide, and paused exact frames are at most 1280×720, so some softness on large displays is expected and is not a defect. The global bar, command bar, panels, range controls, transport, readiness text, frame identity, and other player chrome are absent. The temporary seek overlay is the exception: it shows the current-time label, movie-position bar, and duration label together in one row, as in the normal player. | The movie is the only persistent content. |
| D4 | Moving the pointer reveals the seek row from D3 as a temporary overlay. Away from the row, it and the pointer hide after 3 seconds without actual pointer movement. They remain visible while the row is hovered or the bar is dragged. A still pointer, including same-coordinate mouse events caused by layout, does not restart the timer. A drag ending restarts the timer and returns focus to the player root. There is no fade or other motion to disable for reduced-motion users. | The bar remains usable without permanent controls or a reveal/hide loop. |
| D5 | Dragging the bar retains its normal mode-dependent seek behavior. Clicking the movie picture does nothing, and interacting with the bar never toggles playback. | Pointer interaction is limited to seeking; playback remains a keyboard action. |
| D6 | `F` toggles movie full screen off as well as on. `Escape` uses the browser's native full screen exit; any exit, whether requested by the app or not, is recognized through `fullscreenchange`. Every existing GIF keyboard command remains available in full screen except `E` extraction, which is ignored there. | One exit path restores state even if the page never receives Escape; extraction cannot begin while its feedback is invisible. |
| D7 | `F` can enter from a focused transport button or Jump-by dropdown. In a text input, textarea, or contenteditable field, typing `f` retains its normal text-editing behavior. After successful entry and after exit, focus is on the player root. The seek bar is not kept visible merely because it has focus. If it is about to hide while focused, focus returns to the player root. | Space must not also activate a focused button; the dropdown must not suppress shortcuts; text editing and hidden-control focus must remain predictable. |
| D8 | Entering or leaving full screen by itself does not change the review session, seek position, playback or exact-scrub mode, loop preview, staged endpoints, or saved capture data. A playing movie continues to advance naturally. Full screen is not a shell screen change and must not rerun screen activation, call `mount`, or call `attachSession`; an independent source change can still call `attachSession` as described in D12. | Those lifecycle calls reset the player or abandon refinement when used for a full screen toggle. |
| D9 | Collection-specific full screen behavior must check whether Collection full screen review is active, not merely whether the document has any full screen element. Movie full screen must not set `body.fs-active`, hide dialogs through Collection CSS, apply Collection grid slots, start its rotation timer, change its toolbar button, skip normal grid layout, close Collection zoom, or rerender the Collection grid on exit. | A `fullscreenchange` event currently reaches Collection handling regardless of the active screen. |
| D10 | Full screen presentation becomes active only after `fullscreenchange` confirms that the player root entered. A rejected request leaves the normal workspace and focus intact and reports a recoverable failure there. Repeated or overlapping entry and exit requests settle to one coherent state. | A failed request must not leave hidden chrome or a half-entered mode. |
| D11 | The GIF shortcut map lists `F` for enter/exit and `Escape` for exit. A full screen button appears in the shared player's normal transport and is disabled until D1's readiness condition holds; it is hidden in full screen. | The command is discoverable and usable without a keyboard in the normal view. |
| D12 | Full screen does not change saved side-panel fold states. Exit restores the workspace without replaying panel entrance or folding animations. Moving the player to another screen host may cause the browser to exit full screen. When the shared player attaches a different review session, including no session during preparation, it exits movie full screen and shows the replacement only in the normal view. If that same session closes or loses exact readiness, the player exits full screen. It also exits for a session-ending playback failure when an existing state change or error event reliably identifies that failure. A recoverable operation error, such as a failed seek, does not force exit. If a native crash provides no reliable terminal signal, `Escape` remains the way to return to the normal workspace and see the error; adding that signal is separate work. Screen changes and player disposal also end the mode and remove its pointer timers and input state. | This is a temporary view of the same workspace, not a new visit to it. The full-screen feature uses the existing review-session contract. |
| D13 | App-wide full screen handling continues to apply to both movie and Collection full screen. Entering either mode closes an already open global utility, such as the Activity panel or shortcut map, before mode-specific handling. An error logged during movie full screen must not auto-open the Activity panel or move focus away from the player. The error remains recorded, and the Activity indicator shows it after exit. | A utility outside the full-screen player element would be invisible and could keep or steal focus. |

## Acceptance behavior

| ID | Decisions | Observable check |
|---|---|---|
| A1 | D1, D10, D11 | `F` and the normal-view button enter true display full screen only after exact review is ready. `F` does nothing with no movie or no review session in Collection-clip Refine, while preparing, or after preparation failure. A rejected request leaves normal chrome visible and reports the failure. |
| A2 | D2, D3, D8 | In GIF Extraction and each Refine context, the uncropped movie fills the display with black unused space and no surrounding controls. Entry and exit preserve paused exact frames, active playback, running loop preview, staged endpoints, and range data; playback continues advancing when it was already running. |
| A3 | D3, D4, D5, D7 | Moving the pointer reveals one row containing current time, the seek bar, and movie duration. Away from the row, it and the pointer hide after 3 seconds of inactivity and stay hidden when the pointer stays still despite layout-generated mouse events. The row and pointer remain visible while it is hovered or the bar is dragged. Dragging uses the current seek/scrub behavior and returns focus to the player afterward. Clicking the movie does nothing. |
| A4 | D6, D7 | Immediately after entry and exit, `Q`, `W`, `A`, `S`, `Z`, `X`, `Space`, arrow keys, and top-row `1`–`5` work whenever their ordinary eligibility rules allow, even if a button or the Jump-by dropdown held focus before entry. Typing `f` in a text input, textarea, or contenteditable field inserts text instead of entering full screen. In full screen, `E` never starts extraction; immediately after exit, `E` again works when eligible. Space invokes play/pause exactly once. |
| A5 | D6, D8, D10 | `F` from movie full screen exits. `Escape` or any other exit not started by the app also restores the normal GIF workspace via `fullscreenchange`. Held-arrow state is released safely across both transitions, without an extra step or stuck repeat. |
| A6 | D9, D12 | Entering or exiting movie full screen never activates Collection's `fs-active` CSS, hidden-dialog rule, slot layout, rotation timer, toolbar state, zoom closing, grid layout suppression, or exit rerender. Previously folded panels remain folded, and exit does not replay panel animations. |
| A7 | D8, D10, D12 | Attaching a different review session, including no session during preparation, exits movie full screen. The replacement movie is shown only after normal presentation returns. Closure or loss of exact readiness in the same session exits; a session-ending playback failure also exits when the existing events identify it reliably. A recoverable seek error does not force exit. If a native crash has no reliable terminal signal, `Escape` exits to visible error feedback. Moving the player to another screen host or disposing it cleans up timers and input. A failed or overlapping request never leaves the screen hidden or the player detached. |
| A8 | D11 | The shortcut map for all three GIF contexts shows `F` and `Escape`; the normal-view full screen button accurately reflects readiness and is absent in full screen. |
| A9 | D2, D7, D13 | An Activity panel or shortcut map already open when movie full screen begins closes, and focus moves to the player root. An error raised during movie full screen is recorded without opening the Activity panel or moving focus from the player. After exit, the Activity indicator shows the error and the user can open its details. |

The user-visible goal is to review and operate on the same movie and range at display size, then return to the same GIF workspace without losing position or state. Focused automated checks should cover routing, readiness, focus, and Collection isolation. Verify visual fit, pointer timing, seeking, and continuity with real media in the running Electron app.

## Plan handoff

- Classify every existing `isFullscreen()` call by ownership. In `src/app/app-controller.ts`, review the Collection zoom and context-menu guards near `openZoomForClip`, `openZoomEditMenu`, and the grid context menu separately from Activity's app-wide auto-open suppression. Keep the Activity suppression for any full screen mode (D13).
- Check the layout of the GIF screen's player host when the browser lifts the player root into full screen. Leaving and returning must not collapse the host into a disruptive relayout or cause a visible jump on exit (D12).

## Rejected alternatives

- R1: Reuse Collection's `FullscreenSession` or its `fs-active` state — rejected because its grid, timer, toolbar, and dialog rules are specific to Collection; superseded by D2 and D9.
- R2: Register movie full screen as another shell screen — rejected because screen deactivation abandons Refine state and activation reattaches the player; superseded by D8.
- R3: Full screen the whole document — rejected because it exposes Collection's document-wide full screen coupling and requires separately hiding shell surfaces; superseded by D2 and D9.
- R4: Click the movie to toggle playback — rejected at the user's direction; superseded by D5.
- R5: Keep the seek row visible while its bar is focused — rejected because focus could hold the overlay open indefinitely; superseded by D4 and D7.
