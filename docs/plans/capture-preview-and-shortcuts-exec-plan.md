# Add measured A–B capture preview and GIF shortcuts

## Why this matters

The user wants to inspect exact Start and End pictures and quickly watch a normal-speed loop while adjusting a GIF capture. The loop is a review aid: responsive revisions and behavior demonstrated in the actual player matter more than a by-construction boundary guarantee. Silence is a simplification preference, not a requirement; audible looping is acceptable. GIF Extraction and Refine Gif must share Q/W marks, A/S jumps, Z loop, Space pause/resume, X lock/commit, E extract, and arrow stepping. The revised behavior is in `docs/specs/capture-preview-and-shortcuts-spec.md`; both documents are signed off. The user provisionally accepts the recorded A–B boundary misses for delivery and will manually decide whether the loop mechanism is acceptable on real clips in the final milestone.

**User-visible completion goal:** In the running Electron app, an exact draft, selected locked range, or staged Refine pair can jump to exact endpoints and loop on the already open proxy at usable 1×; Space pauses into exact scrub and resumes that loop from the displayed in-range frame, and preview leaves ordinary playback audio in its prior state. Record boundary misses and outside pictures honestly. The user then tries real clips and signs off on the loop mechanism or requests its replacement.

## A–B proxy loop solution

### Timing and state contract

After FFmpeg finishes encoding and the prepared proxy BestSource index is built, read each proxy ordinal's integer PTS and rational timebase once and persist a compact, versioned loop-timeline sidecar keyed to the prepared proxy identity. Include the indexed final duration or mark its absence. Validate its frame count against the existing ordinal-identity map. The existing prepared-review manifest and its required files continue to validate proxy playback and exact scrub independently of this optional sidecar. On a cache hit, load and validate the sidecar; if absent or invalid, regenerate it from the existing proxy index without rebuilding the proxy or canonical index. If regeneration still fails, disable only exact loop preview with a clear reason. Publish the sidecar atomically so a partial write cannot be read as valid. The host keeps its file path and uses the timeline to convert selected frame numbers into loop times; the renderer supplies frame numbers, never a cache path. Loop setup reads Start, End, and End+1 by ordinal; for End at the proxy's last picture, use indexed duration or estimate hold from the preceding positive PTS gap. Treat proxy PTS ticks and LibVLC player microseconds as separate domains: after validating the per-proxy mapping `T`, compare a sampled player time with the timeline converted through `T` and choose the greatest ordinal whose converted time is at or before the sample. Use indexed proxy times rather than canonical `reviewTimeUs` or inferred FPS, and read frame metadata without decoding the full proxy again. Measure the extra preparation time and timeline size; ordinary proxy playback must remain available while exact preparation continues. At the host boundary, check that Start and End are whole, nonnegative frame numbers that JavaScript represents exactly and that both are within this proxy's frame count; require Start < End, a live review session, strictly ordered proxy PTS, and player times representable as nonnegative integer microseconds.

Let `A_pts`, `E_pts`, and `N_pts` be Start, End, and End+1 integer proxy PTS ticks; for End at the last frame, `N_pts` is the estimated end of its display interval. Require `A_pts < E_pts < N_pts`. Let `Δ_pts=N_pts−E_pts`. Represent the tunable fraction `f` as a bounded rational number and choose `B_pts=E_pts+round(f×Δ_pts)` using checked integer/rational arithmetic; round to the nearest integer with exact half cases upward for these nonnegative offsets, and use the same stated rule for tick-to-microsecond conversion. Require `E_pts < B_pts < N_pts`; otherwise report “Loop interval is too short.” Convert each candidate to integer LibVLC player microseconds with the validated per-proxy timebase/origin mapping `T`, using an explicit rounding rule: `A_base=T(A_pts)`, `E=T(E_pts)`, `B=T(B_pts)`, and `N=T(N_pts)`. For this provisional candidate, pass `A=A_base−1 μs` to LibVLC when Start is nonzero and `A=A_base` for Start zero, while exact jumps and capture retain Start's ordinal. Recheck `A < B` and `E < B < N` after conversion; if rounding collapses either interior margin, reject the interval rather than silently using E or N. Unit-check rational conversion, rounding, overflow, negative/unrepresentable player times, and rejection at short intervals. Start the player probe with the central fraction; try at most one earlier and one later fraction in short diagnostics if a boundary, End+1, seam, or speed failure is plausibly affected by B placement. Record actual left/right margins in player microseconds (`B−E`, `N−B`) and the chosen policy. The margins tune behavior; neither margin guarantees the pictures because the pinned player schedules a deadline and seek. Validate the actual proxy timebase and conversion rather than assuming every movie uses millisecond ticks.

For the Milestone 1 three-cycle diagnostic only, permit a provisional `T₀(p)=round((p−firstPts)×timebaseUs)` with zero player origin, labelled as fixture-specific and unverified. If it cannot produce a useful painted trace, adjust and record the provisional origin for that fixture; do not treat that diagnostic as evidence of a production clock rule. Before Milestone 2 acceptance or production Z, establish a deterministic proxy-metadata-to-player-clock rule `T` during development. Start with `T(p)=origin(proxy)+round((p−firstPts)×timebaseUs)` using checked rational arithmetic; determine `origin(proxy)` from indexed proxy/container metadata according to a rule verified for the pinned player and proxy profile, not from a fixture-specific constant. Use controlled playback/seeks to known ordinal tiles, including the first and noninitial frames, and correlate their paints with the LibVLC timer across CFR, VFR, timestamp-normalized, and nonzero-first-proxy-PTS fixtures when the finished proxy profile supports that start. Record the rule, rounding, observed alignment and drift, and the metadata it needs.
